Today’s Synthesis

If you’re shipping an on-device agent with long-term memory, treat forgetting as a safety control, not a cleanup step. The memory filtering paper says hard eviction can delete query-critical facts when the resolver is wrong, so gate deletion behind confidence, provenance, and a cheap retrieval replay. Pair that with the hallucination detector audit : don’t trust detector rankings from 7B+ models once you’re on 4-bit local models. Run your own small eval on the quantized build before wiring detectors into memory writes. Then use LoRAWeaver to route task-specific adapters without retraining a router every time a new skill lands. The practical build: store memories with uncertainty tags, route queries through the relevant adapter, and only promote a memory to permanent state if a local detector passes and a replay query still resolves. That gives you a cheaper, less brittle memory system than “delete old stuff” or “keep everything forever.” It also keeps evaluation close to the deployment target, where quantization bugs usually hide.
