## Research Worth Reading
- **[When Should LLM Agents Forget? Memory Filtering Under Query-Critical Resolver Errors](https://arxiv.org/abs/2611.17338)** — Hard-filtering stale facts can nuke query-critical info when the resolver is wrong. If you’re building agent memory, this is a reminder that aggressive forgetting needs uncertainty-aware guardrails.
- **[Does the Ranking Hold? A Practitioner-Facing Audit of Hallucination Detectors on Small, Quantized, On-Device LLMs](https://arxiv.org/abs/2611.17339)** — Audits hallucination detectors on small quantized on-device LLMs. If you’re deploying 4-bit models, don’t assume detector rankings from big research models survive contact with reality.
- **[LoRAWeaver: Directional Adapter Routing in LoRA Representation Space](https://arxiv.org/abs/2611.17340)** — Routes among LoRA adapters using directional info in LoRA representation space. Useful if you’re serving multiple task adapters and don’t want to retrain an encoder every time someone adds a new one.
- **[Advancing Quantization for R&R Models with Microscaling Formats](https://arxiv.org/abs/2611.17501)** — Tests microscaling quantization for recommendation/ranking models, where throughput matters and precision regressions can kill launches. It’s a systems-y look at squeezing accuracy out of production rankers without breaking them.
- **[Model Annealing: Data-Efficient Learning through Review and Consolidation](https://arxiv.org/abs/2611.17524)** — After a small labeled set is memorized, spend the remaining budget on review/consolidation episodes with re-raised learning rates. A data-efficient alternative to pretending more epochs magically fix everything.
- **[Safety Side Effects of Preventative Persona Steering: An Empirical Audit](https://arxiv.org/abs/2611.17620)** — Audits persona steering during fine-tuning as a preventative safety move, comparing it with inference-time vector subtraction. If you’re trying to suppress sycophancy or hallucination, this is worth reading before you ship a persona vector.

## Today's Synthesis

If you’re shipping an on-device agent with long-term memory, treat forgetting as a safety control, not a cleanup step. The [memory filtering paper](https://arxiv.org/abs/2611.17338) says hard eviction can delete query-critical facts when the resolver is wrong, so gate deletion behind confidence, provenance, and a cheap retrieval replay. Pair that with the [hallucination detector audit](https://arxiv.org/abs/2611.17339): don’t trust detector rankings from 7B+ models once you’re on 4-bit local models. Run your own small eval on the quantized build before wiring detectors into memory writes. Then use [LoRAWeaver](https://arxiv.org/abs/2611.17340) to route task-specific adapters without retraining a router every time a new skill lands. The practical build: store memories with uncertainty tags, route queries through the relevant adapter, and only promote a memory to permanent state if a local detector passes and a replay query still resolves. That gives you a cheaper, less brittle memory system than “delete old stuff” or “keep everything forever.” It also keeps evaluation close to the deployment target, where quantization bugs usually hide.
