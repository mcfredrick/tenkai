## Research Worth Reading
- **[Together Compiler: Continual Compilation for AI Inference](https://arxiv.org/abs/2611.14681)** — Paper on continual compilation for fast-changing inference workloads, model architectures, and traffic patterns. Relevant if you care about compiler design and production serving. 📄
- **[Effective Teacher Support for Reasoning Distillation](https://arxiv.org/abs/2611.14850)** — Distills from only the teacher's top-probability vocabulary fraction rather than full logits, cutting training and storage cost. It sweeps retained support from 100% down to 0.01%.
- **[Cleaning an Agent's History Hurts When the World Still Holds the Error](https://arxiv.org/abs/2611.14654)** — Studies agent history compaction when external state still contains the mistake. Main takeaway: scrubbing internal memory can make things worse if the environment isn't corrected.
- **[SynthCorp: A Platform for Creating Benchmarks for Data Agents](https://arxiv.org/abs/2611.14765)** — Generates benchmarks for LLM data agents by simulating business events that create and mutate corporate data. Gives you synthetic relational DBs, document stores, and catalogs for evaluation. 📄
- **[Robust Task-Aware State Estimation from Pre-trained Perception](https://arxiv.org/abs/2611.14781)** — Tackles brittle state estimation when agents rely on pretrained perception like VLMs. Instead of collapsing uncertainty into one best guess, it keeps task-aware uncertainty in the loop.
- **[When Is Proof-Step Verification Worth Its Cost? Operating Requirements of Certify-or-Decline Verification for Open-Weight Mathematical Reasoning](https://arxiv.org/abs/2611.14794)** — Evaluates proof-step verification with LLM judges that certify or decline answers. Reports precision gains on GPQA, AIME-2025, and MATH-500, plus the cost/coverage trade-off. 📄

## Today's Synthesis

If you’re wiring Claude Code into real pipelines, treat [Claude Code v2.1.325](https://github.com/anthropics/claude-code/releases/tag/v2.1.325) as the boring-but-necessary first step: patch the zstd decoding issue before you spend another afternoon debugging weird agent output. Then pair it with the patterns in [Claude Code best practices for agentic engineering](https://github.com/shanraischan/claude-code-best-practice) so your commands, skills, and context handling stop looking like a pile of prompt spaghetti. The useful move is to make the agent’s history auditable: log tool calls, file diffs, and failed attempts, then inspect whether similar failures cluster around the same context or retrieval path. The paper [Cleaning an Agent's History Hurts When the World Still Holds the Error](https://arxiv.org/abs/2611.14654) makes the point sharply: compaction can backfire if the environment still contains the mistake. So don’t just scrub the transcript; fix the external state, tests, or docs the agent is reading. That turns “the model forgot” into a concrete engineering bug you can reproduce, patch, and regression-test.
