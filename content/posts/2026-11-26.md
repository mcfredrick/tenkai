## 🥧 Open Source Releases

- **[agent-strace 0.125.0](https://pypi.org/project/agent-strace/0.125.0/)** — Captures and replays agent tool calls, LLM requests, and decision points. Basically strace for agents, which is the kind of leftover debugging you can reheat without cloud sauce. 🥧

- **[lcode-cli 0.65.0](https://pypi.org/project/lcode-cli/0.65.0/)** — A local-first terminal coding agent that runs open-weight models via Ollama on local GPUs or Macs. Useful if you want a self-hosted coding assistant that doesn’t phone home for gravy. 🍂

- **[hexiel 0.9.23](https://pypi.org/project/hexiel/0.9.23/)** — Open-source coding agent for terminal and browser, with local Ollama or cloud LLM backends. It’s the self-hosted casserole dish for teams avoiding another vendor subscription. 🌽

- **[karachay-shazam 0.1.0](https://pypi.org/project/karachay-shazam/0.1.0/)** — Audio fingerprinting with a ResNet-18 ONNX model and FAISS indexing, aimed at Karachay-Balkar songs. A tiny neural retrieval recipe for niche music identification. 🥧

- **[smartmemory-core 2.0.9](https://pypi.org/project/smartmemory-core/2.0.9/)** — A multi-layer memory stack mixing graph databases, vector stores, and processing pipelines. It’s infrastructure for agents that need to remember more than last night’s leftovers. 🍂

- **[lifeboatrouter 0.1.9](https://pypi.org/project/lifeboatrouter/0.1.9/)** — Routes vLLM, SGLang, or Lifeboat servers into a metered OpenAI-compatible token marketplace with a built-in UI. Handy for serving quotas, internal billing, or rationing GPU turkey slices. 🌽

## 📄 Research Worth Reading

- **[ContextLure: Exploiting Benign Conversation History for Indirect Prompt Injection](https://arxiv.org/abs/2611.31424)** — Shows how benign conversation history can be seasoned into an indirect prompt injection against tool-using agents. If you’re building long-horizon agents, this is the security warning label on the cranberry can. 🦃

- **[Taxi: Analyzing Agents at (Real) Scale](https://arxiv.org/abs/2611.31457)** — A system for debugging, clustering, and monitoring agents at millions of steps, with a taxonomy over agent traces. It’s the big serving tray for large-scale agent trace analysis. 🍂

- **[One Step, Four Clocks: How GUI Agents Fall Out of Step](https://arxiv.org/abs/2611.31522)** — Models GUI-agent failures through four timing events, showing latency alone doesn’t explain actions going stale mid-deliberation. Introduces ChronotopeGym for studying desynchronization failures, like a clock that missed dinner. 🥧

- **[Neighbor Crowding Predicts Feature Stability in Sparse Autoencoders](https://arxiv.org/abs/2611.33182)** — Finds that crowding in SAE feature space predicts stable features versus initialization artifacts. Useful for mechanistic interpretability when you don’t want to train a pile of SAE seeds just to compare notes. 🌽

- **[KiRA: Kronecker Input-Gated Rank Adaptation for Parameter-Efficient Fine-Tuning](https://arxiv.org/abs/2611.33236)** — A PEFT method using Kronecker-factored, input-gated rank adaptation to get past the fixed low-rank adapter bottleneck while staying parameter-efficient. For engineers who want more capacity without a full model roast. 🍂

- **[One Token, Many Lessons: Sliding-Window Attention within Gated Delta Networks](https://arxiv.org/abs/2611.33257)** — Reads linear attention as test-time regression, where the recurrent state is an online-learned model, then adds sliding-window attention to gated delta networks. Relevant for long-sequence, memory-efficient architecture work. 🦃

## Today's Synthesis

For the holiday table, build a local agent-testing buffet: use [agent-strace 0.125.0](https://pypi.org/project/agent-strace/0.125.0/) to capture tool calls, LLM requests, and decision points while your agent tries to book a dinner reservation or merge a pull request. Then replay a benign-looking conversation history using the attack pattern from [ContextLure](https://arxiv.org/abs/2611.31424), because innocent context can still season a prompt-injection path if your tool loop trusts too much. Finally, dump the resulting traces into [Taxi](https://arxiv.org/abs/2611.31457) and cluster failures by its taxonomy, so you can separate “model misunderstood the task” from “tool call raced the user’s intent” or “retrieved context went stale.” The engineer move is to turn this into a pre-release check: record a trace set, reheat it with adversarial-but-polite history, then gate deploys on new failure clusters. Keep the harness local, version the traces, and rerun it whenever prompts, tools, or model routing change. That gives you a repeatable way to inspect agent behavior before users find the burnt bits. If you already have CI, run it on every prompt change and attach the failing trace to the ticket. 🦃
