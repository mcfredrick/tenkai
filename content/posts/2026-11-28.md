## Model Releases

## Open Source Releases

- **[ezco 0.2.1](https://pypi.org/project/ezco/0.2.1/)** — 🛠️ A guard that sniffs out slopsquat packages, leaked secrets, and poisoned agent config files at commit, install, and clone time. The threat model here is real: your coding agent will happily read whatever `AGENTS.md` it finds and treat it as instructions.
- **[remgu 0.4.0](https://pypi.org/project/remgu/0.4.0/)** — Experiment lifecycle management for reproducible ML work: tracking, organizing, and generally being the thing you swore you'd set up after the last "which config produced this number?" incident. Yet another option in a very crowded shelf.
- **[dotcode-sdk 0.3.0](https://pypi.org/project/dotcode-sdk/0.3.0/)** — Python SDK for embedding a multi-LLM coding agent in your own app, with Anthropic, OpenAI, Azure, Gemini, DeepSeek, and Ollama behind one interface. Handy if you want agent-assisted flows without picking a vendor and marrying it.

## AI Dev Tools

- **[thedotmack/claude-mem](https://github.com/thedotmack/claude-mem)** — Persistent memory layer for agents: captures what happened in a session, compresses it, and reinjects the relevant bits next time via a local vector DB. Supports multiple runtimes, so you're not locked to one CLI. The pitch is obvious — stop re-explaining your repo layout every session — and the failure mode to watch is stale context confidently steering the agent wrong.

## Today's Synthesis

Here's the thing nobody's packaging yet: [claude-mem](https://github.com/thedotmack/claude-mem) turns session history into a durable input, and durable inputs are exactly what [ezco](https://pypi.org/project/ezco/0.2.1/) exists to vet — except ezco checks commit, install, and clone time, not the vector DB your agent reads on startup. Poison once in a cloned repo and the compressed summary carries it into every future session, long after anyone stopped watching that repo. Concrete move: tag each memory entry with the repo URL and commit it came from, then quarantine entries from untrusted clones — retrieve them, don't inject them until ezco has cleared the source. Diff the memory store in CI like a lockfile; a summary that rewrites itself overnight is a review request, not background noise. If you're embedding through [dotcode-sdk](https://pypi.org/project/dotcode-sdk/0.3.0/), that check belongs in your tool-permission layer, not in a vendor default you haven't read. Same logic argues for keeping the loop local — self-hosted inference, memory DB on your own disk — because the alternative is mailing your repo layout to someone else's endpoint every morning.
