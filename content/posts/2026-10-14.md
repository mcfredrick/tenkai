## Model Releases

- [LiquidAI LFM2.5-24B-A2B MoE Language Model](https://huggingface.co/LiquidAI/LFM2.5-24B-A2B) — LiquidAI's LFM2.5-24B-A2B is a Mixture-of-Experts language model optimized for edge deployment, supporting multilingual conversational AI and text generation, with architecture detailed in arXiv 2511.23404.
- [MiniCPM-V 4.7-1B On-Device Multimodal Model](https://huggingface.co/openbmb/MiniCPM-V-4.7-1B) — MiniCPM-V 4.7-1B is a compact, on-device multimodal model supporting image-text conversation, designed for lightweight deployment on edge devices while maintaining conversational capabilities through transformers and safetensors.
- [Fishaudio Drama-3 Multilingual TTS Model](https://huggingface.co/fishaudio/drama-3) — Fishaudio Drama-3 is a multilingual text-to-speech and audio-editing model supporting emotional speech generation, multi-speaker scenarios, and integrates bsgemm-moe optimization for efficient inference, with arXiv 2610.18010 detailing the architecture.

## Open Source Releases

- [agent-intern 0.33.0: MCP server for multi-agent CLI orchestration](https://pypi.org/project/agent-intern/0.33.0/) — An MCP server that bridges diverse code CLIs—including OpenAI Codex, GitHub Copilot, Cursor, and others—allowing Claude Code to orchestrate them as sub-agents for modular, multi-agent development workflows.
- [anthropics/claude-code v2.1.299: File mention paths env var and idle compaction](https://github.com/anthropics/claude-code/releases/tag/v2.1.299) — Release adds CLAUDE_CODE_DISABLE_FILE_MENTIONS environment variable controlling whether Claude reads @ file mention paths or contents, and implements idle compaction for 200K+ token conversations left idle ~54 minutes before the one-hour prompt cache expires, improving efficiency for long-running sessions
- [gnosis-air 0.1.25: AI agent conversation analysis CLI](https://pypi.org/project/gnosis-air/0.1.25/) — A CLI tool for ingesting and analyzing AI agent conversation logs from Claude Code and Codex, providing intent classification, friction detection, and a cross-session knowledge graph to improve agent reliability and workflow understanding.
- [doc-ai-slopcheck 1.2.0: Deterministic scanner for AI-generated code failures](https://pypi.org/project/doc-ai-slopcheck/1.2.0/) — A deterministic static analysis tool with 73 rules across Python, JavaScript/TypeScript, Go, C/C++, and SQL, targeting common failure patterns and antipatterns in code produced by or for AI systems.
- [astscribe 0.12.0: L-free explanation of unfamiliar ML notebooks](https://pypi.org/project/astscribe/0.12.0/) — A Jupyter-integrated tool that analyzes ML notebook structure, variable flows, and cell dependencies to provide evidence-backed explanations without using LLMs, aiding engineers in auditing and onboarding legacy workflows.
- [graph-knowledge-doc-parser 0.2.16: LLM doc parser with graph awareness](https://pypi.org/project/graph-knowledge-doc-parser/0.2.16/) — An LLM-powered documentation parser that integrates graph knowledge to improve semantic understanding, entity resolution, and structural preservation, supporting RAG pipelines and technical documentation workflows.

## Today's Synthesis

When inheriting an ML codebase shaped by previous LLM assistance, you can systematically audit logic, flag risky code, and structure docs for retrieval by running three targeted tools in sequence. [astscribe 0.12.0](https://pypi.org/project/astscribe/0.12.0/) analyzes notebook structure, variable flows, and cell dependencies without adding another LLM layer, giving you a clean map of what each cell actually does. Immediately follow with [doc-ai-slopcheck 1.2.0](https://pypi.org/project/doc-ai-slopcheck/1.2.0/), which applies 73 deterministic rules across Python, JavaScript/TypeScript, Go, and C/C++ to surface common AI-generated antipatterns—missing imports, unsafe assumptions, dead logic—before they reach production. Finally, [graph-knowledge-doc-parser 0.2.16](https://pypi.org/project/graph-knowledge-doc-parser/0.2.16/) ingests your READMEs and design docs, using graph awareness to resolve entities, preserve structure, and feed clean context into your RAG pipeline. The engineer-actionable idea: configure these as a post-commit CI step. You’ll get a triage report stating exactly what the notebook accomplishes, where the generated code is fragile, and which documentation chunks are queryable, turning opaque AI-assisted workflows into auditable, recoverable artifacts.
