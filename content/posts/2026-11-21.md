## Model Releases
- **[thinkingmachines/Inkling-2-Mini](https://huggingface.co/thinkingmachines/Inkling-2-Mini)** — 🤖 A conversational image-text-to-text MoE released under Apache-2.0. Handy if you want a permissive multimodal model with Transformers/Safetensors packaging and endpoint-friendly bits.
- **[unsloth/Inkling-2-Mini-GGUF](https://huggingface.co/unsloth/Inkling-2-Mini-GGUF)** — GGUF quants of Inkling-2-Mini with imatrix calibration. Mostly here for local or endpoint inference where you want the MoE model at a friendlier memory footprint.
- **[apple/DepthPro2](https://huggingface.co/apple/DepthPro2)** — Apple's metric, monocular, and video depth estimator. Worth a look for 3D perception, reconstruction, or depth-aware generation, assuming you don't mind Apple's ecosystem gravity.
- **[Cloudflare/clairic](https://huggingface.co/Cloudflare/clairic)** — A fine-tuned Qwen3.8-27B aimed at multimodal structured output and extraction. Useful if you need conversational extraction with custom code, less so if you just want a plain chat model.

## Open Source Releases
- **[sandbox-ai-app 0.1.188](https://pypi.org/project/sandbox-ai-app/0.1.188/)** — 🛠️ Sandbox runner for AI coding agents with rootless Podman/Bubblewrap and an egress firewall. Useful if you want to let Claude Code, Codex, or OpenCode run without giving them the whole box.
- **[ai-oriented-a2a 0.3.3](https://pypi.org/project/ai-oriented-a2a/0.3.3/)** — Small stdlib helpers for A2A peer protocol, including Experience Packets, optional HMAC auth, and replay protection. A sane starting point if you're building interoperable agent-to-agent services.
- **[agentic-metric-x 0.8.25](https://pypi.org/project/agentic-metric-x/0.8.25/)** — 🔥 Tracks token usage and cost for coding agents like Claude Code and Codex, locally or over SSH. Good for keeping an eye on agent spend without building your own meter.
- **[aria-mcp-server 0.3.0](https://pypi.org/project/aria-mcp-server/0.3.0/)** — MCP server exposing PubMed, ClinicalTrials.gov, and ISRCTN search. Handy for biomedical literature and trial discovery if agents need structured tool access.
- **[llmcapa 0.5.94](https://pypi.org/project/llmcapa/0.5.94/)** — Offline lookup for model capabilities like context window, modalities, and feature support. Nice for selecting or validating models without hitting live APIs.
- **[scnmf-gpu 0.4.6](https://pypi.org/project/scnmf-gpu/0.4.6/)** — PyTorch GPU implementation of sparse conditional joint NMF for single-cell RNA-seq integration. Targets interpretable metagene discovery and faster large single-cell workloads.

## Today's Synthesis

The pattern worth stealing this week: put your coding agents in a box you actually control, then measure what they burn. [sandbox-ai-app](https://pypi.org/project/sandbox-ai-app/0.1.188/) already gives you rootless Podman or Bubblewrap plus an egress firewall, so Claude Code, Codex, or OpenCode can run without inheriting your whole home directory. Wire that to [agentic-metric-x](https://pypi.org/project/agentic-metric-x/0.8.25/) and you get per-session token and cost accounting, locally or over SSH — no dashboard to build, no billing surprises at the end of the month. Then treat the firewall rules as your actual tool policy: allowlist only the endpoints your agent genuinely needs, and serve the rest through something like [aria-mcp-server](https://pypi.org/project/aria-mcp-server/0.3.0/) if your domain is biomedical. Concrete first step: one container image, one allowlist, one week of cost data. Track spend per repo rather than per seat — that's the number that changes how people prompt. If the totals look sane, promote the setup to the team; if not, you found out cheaply, and the sandbox was pulling its weight the whole time.
