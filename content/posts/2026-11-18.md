## Model Releases
- **[tencent/Hy4-flash](https://huggingface.co/tencent/Hy4-flash)** — A multimodal mixture-of-experts instruct model with safetensors weights and endpoint compatibility. If you're poking at large MoE image-text assistants, it's a candidate to benchmark; if you just need a tiny classifier, it's overkill. 🤖
- **[apple/FastFrames-L](https://huggingface.co/apple/FastFrames-L)** — Apple's text-to-video model, fine-tuned from Wan2.1-T2V-14B and shipped with an arXiv reference. Worth a look if you're chasing faster or better video synthesis, less so if your pipeline only needs still images.

## Open Source Releases
- **[OpenCode v2.3.2 fixes GPT-6.2 prompt caching across Responses routes](https://github.com/anomalyco/opencode/releases/tag/v2.3.2)** — GPT-6.2 won't cache system prompts sent through the Responses instructions field, so OpenCode now puts the system prompt in a leading developer message to make caching work. If you're watching token bills on agent loops, this is a small but useful fix. 🛠️
- **[ctxprune 0.3.2](https://pypi.org/project/ctxprune/0.3.2/)** — Lossless compression for tool outputs in coding agents, plus token-pruning helpers for prompts and RAG pipelines. It has LangChain and LlamaIndex integrations, which is either handy or a sign your stack is already too big.

## Research Worth Reading
- **[Language Models Can Rewrite Their Own Weights](https://arxiv.org/abs/2611.21885)** — The paper asks whether a model can edit its own weights instead of relying on prompts, scaffolds, or another training run. If the reported capability shifts hold up, self-modification becomes less sci-fi and more “please don’t let this touch prod.” 📄
- **[DNeo: Your Parallel Draft Model Needs Better Target Feature Encoding](https://arxiv.org/abs/2611.21925)** — DNeo improves how parallel draft models encode target-model features for speculative-diffusion decoding. The goal is more accepted draft tokens during parallel verification, which could mean better throughput for diffusion-based language models.
- **[KV-LTM: Persistent Per-Session KV Caches as Long-Term Memory for Personal Assistants](https://arxiv.org/abs/2611.21998)** — This one treats per-session KV caches as long-term memory instead of relying on retrieval or summaries. The LongMemEval comparison suggests keeping KV state can avoid content loss, though cache storage and eviction are now your problem.
- **[VisHead-Spec: Head-Routed Visual Attention for Multimodal Speculative Decoding](https://arxiv.org/abs/2611.21839)** — Head-routed visual attention for multimodal speculative decoding, aimed at preserving speedup when serving many requests at once. If you're running vision-language models under concurrency, the long-image-token overhead is the part to watch.
- **[The Hidden Cost of MoE Diffusion Decoding: Profiling and Fixing the Sampler](https://arxiv.org/abs/2611.21852)** — Profiling a 26B diffusion MoE on a bandwidth-bound edge accelerator and finding that sampling/stopping over the full canvas-by-vocabulary logits tensor is not free. The proposed sampler fixes are relevant if you're optimizing diffusion decoding outside datacenter comfort zones.
- **[Chain-of-Thought Controllability Can Reduce Chain-of-Thought Monitorability](https://arxiv.org/abs/2611.21799)** — Trains models to control their reasoning traces with persona-control supervision, then checks whether CoT monitoring still works. The uncomfortable result: more controllability can make the traces less monitorable, which is a bad combo for oversight. 🔥

## AI Dev Tools
- **[OpenVINO: toolkit for optimizing and deploying AI inference](https://github.com/openvinotoolkit/openvino)** — Open-source toolkit for optimizing and deploying inference across Intel and other hardware. Useful if you need model conversion, runtime deployment, and perf tooling without building the whole serving stack yourself.
- **[learn-claude-code: minimal agent harness tutorial](https://github.com/shareAI-lab/learn-claude-code)** — Builds a minimal Claude Code-like agent harness from scratch in Bash. Good for understanding agent loops, tool use, and harness design before you wrap everything in a framework.

## Today's Synthesis

The most practical takeaway from today’s batch is that agent cost and reliability are becoming context-engineering problems, not just model-choice problems. The [OpenCode v2.3.2 fix](https://github.com/anomalyco/opencode/releases/tag/v2.3.2) shows how much prompt caching can depend on boring details like where the system prompt lives, so if you’re running long agent loops, audit your provider’s cache boundaries before optimizing anything else. Pair that with [ctxprune 0.3.2](https://pypi.org/project/ctxprune/0.3.2/) to compress tool outputs and prune noisy retrieval chunks before they enter the context window; the win is not just fewer tokens, but fewer irrelevant tokens competing for attention. For teams building their own harness, [learn-claude-code](https://github.com/shareAI-lab/learn-claude-code) is a useful minimal reference for seeing how tool calls, prompts, and loop state fit together without framework fog. A concrete experiment: take one production agent, instrument cache hit rate, token usage, and task success, then compare baseline, cache-aware prompt placement, and ctxprune-assisted tool-output compression. If success holds while cost drops, you’ve found the least glamorous optimization that actually matters.
