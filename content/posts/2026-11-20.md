## Model Releases
- **[HuggingFaceTB/SmolVLM2-256M-Video-Instruct](https://huggingface.co/HuggingFaceTB/SmolVLM2-256M-Video-Instruct)** 🤖 — A 256M-parameter video-capable vision-language model with Transformers and ONNX support. Useful if you need video understanding on tight memory budgets, though 256M will still have opinions about what “small” means.

## Open Source Releases
- **[Claude Code v2.1.329](https://github.com/anthropics/claude-code/releases/tag/v2.1.329)** 🛠️ — Adds trust and visibility warnings for hooks, including folder-hook declarations and managed hooks that fail to load in non-interactive hosts. It also surfaces scheduled tasks, /loop wakeups, goals, and conversation forks in /tasks, which is handy when your agent setup starts feeling like a haunted CI pipeline.

## Research Worth Reading
- **[Why Sub-4-Bit Vision CNNs Collapse and Where Mixed-Precision Recovery Stops](https://arxiv.org/abs/2611.23445)** 📄 — Pokes at why vision CNNs fall apart under 4-bit quantization and where mixed-precision patches can claw back accuracy. If you’re shipping compressed vision models, this is the kind of failure-mode map you want before production finds it for you.
- **[Watch Where You Linearize: Predicting and Correcting Model-Merging Interference](https://arxiv.org/abs/2611.25000)** — Uses first-order directional derivatives to predict interference between task vectors before you merge them. That can make coefficient search cheaper and help you spot destructive merges before they become a debugging afternoon.
- **[Separating Interpretability and Reconstruction in Sparse Autoencoders](https://arxiv.org/abs/2611.25165)** 📄 — Argues that sparse autoencoders shouldn’t be forced to serve both reconstruction fidelity and clean, interpretable features at the same time. Splitting those objectives may make mechanistic interpretability work less like interpretive dance.
- **[Training Language Models for Introspective Oversight](https://arxiv.org/abs/2611.23365)** — Trains language models to support introspective oversight of behaviors like reward hacking, deception, and sycophancy. The pitch is better self-reporting and monitoring than just asking the transcript follow-up questions and hoping for honesty.
- **[HardwareDx: A Foundational Graph Model System for Datacenter Machine Repairs](https://arxiv.org/abs/2611.23398)** — Frames datacenter hardware diagnosis and repair as a graph-learning problem, with the goal of cutting downtime in large AI clusters. If your cluster’s failure modes have started to look like a social network, this one is relevant.
- **[GUARD: Stabilizing Recursive Self-Improvement with Regret Guidance](https://arxiv.org/abs/2611.23476)** 🔥 — Proposes regret-guided stabilization for recursive self-improvement in agent harnesses without touching weights. It’s aimed at making self-edited prompts, skills, and memory safer by catching regressions before the agent confidently improves itself into a brick.

## Today's Synthesis

If you’re running agent harnesses that edit their own prompts, skills, or memory, treat those edits like model merges rather than casual config changes. The [GUARD: Stabilizing Recursive Self-Improvement with Regret Guidance](https://arxiv.org/abs/2611.23476) paper suggests adding a cheap regression gate before an agent commits a self-improvement, and [Claude Code v2.1.329](https://github.com/anthropics/claude-code/releases/tag/v2.1.329) gives you a practical surface for that: surface hooks, scheduled tasks, loop wakeups, goals, and conversation forks in `/tasks` so you can see what changed and when. Pair that with the [Watch Where You Linearize](https://arxiv.org/abs/2611.25000) idea of predicting interference before combining task vectors, and you get a concrete workflow: snapshot the current prompt/tool/memory state, propose the edit as a task-vector-like delta, run a small eval or shadow trace, and only promote it if regret or interference stays below threshold. Log the diff, the eval delta, and the triggering task so a bad self-edit can be reverted without archaeology. That turns self-editing from vibes into a reviewable CI pipeline.
