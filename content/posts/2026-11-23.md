## Research Worth Reading
- **[TOUMAII: A 4.5M-Pair Tool-Calling Preference Dataset and Its Source-Agnostic Generator](https://arxiv.org/abs/2611.26722)** — 📄 A 4.5M-pair preference dataset for tool calling, built around correct API calls versus plausible wrong alternatives. Also ships a source-agnostic generator, which is the interesting part if you need tool-use training data across environments.
- **[CodeReviewBench: An Automated Benchmark for Evaluating the Software Factory](https://arxiv.org/abs/2611.26942)** — An automated benchmark for AI code review quality in realistic software workflows. It fixes a common benchmark flaw by using PR-author judgments instead of third-party reviewers.
- **[Don't Discard Your Rollouts: Reusing Teacher RL Traces for Student Distillation](https://arxiv.org/abs/2611.26803)** — Looks at reusing teacher RL rollouts, including multiple completions and rewards, for student distillation instead of regenerating data from the final teacher. If you’re burning compute on PPO/GRPO-style post-training, the cost angle is the point.
- **[Budget-Aware Predict-and-Verify Theorem Proving with Heterogeneous LLM Solvers](https://arxiv.org/abs/2611.26906)** — BudgetPV routes subgoals to different LLM solvers based on capability and inference cost, then uses predict-and-verify to cut wasted computation. Relevant if you’re orchestrating multiple solvers and care about cost-efficient reasoning.
- **[Self-Evolving Beyond Human-Crafted Experience for EDA Scripting](https://arxiv.org/abs/2611.26912)** — ZhuLong-SE is a self-evolving agent for EDA scripting that learns from execution feedback instead of relying only on hand-crafted knowledge. It targets sparse proprietary APIs and silent failures, which are exactly the annoying parts of EDA toolchains.
- **[Keep the Process, Change the Supplier: Runtime Governance for Tool-Using AI Agents](https://arxiv.org/abs/2611.26966)** — Proposes an execution boundary that mediates tool-using agent actions, separating proposals from business-controlled authorization, context disclosure, and supplier selection. The Open Process Control Plane records uncertain or external effects, which is useful if you need runtime governance instead of vibes.

## Today's Synthesis

If you're distilling a teacher into a student, you're not just copying capability. You're copying its refusals, its tool-call habits, and whatever else it picked up along the way. That's the pitch behind [Don't Discard Your Rollouts](https://arxiv.org/abs/2611.26803): the traces are already paid for, so mining them for near-miss cases costs you almost nothing. Pair that with [safetypulse](https://pypi.org/project/safetypulse/0.1.2/)'s Circuit Integrity Score and you've got a cheap gate. Run the student over a fixed prompt set before and after each distillation run, and fail the build if refusal behavior drifts more than a couple of points. Then add [TOUMAII](https://arxiv.org/abs/2611.26722)'s plausible-wrong tool calls to the same harness. Those are exactly the inputs that slip past a student that learned API shapes from a teacher that never got corrected. Concretely: one CI job, three evals, one threshold, no new training data. The rollouts you already have are the cheapest safety regression suite you'll ever build. The alternative is finding out in production that your 8B model now happily approves wire transfers.
