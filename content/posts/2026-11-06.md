## Research Worth Reading
- **[LowRAM](https://arxiv.org/abs/2611.07025)** — 📄 Identifies that within each attention head, values are largely predictable from keys, proposing low-rank key compression and amortized value storage for test-time KV cache compression. Introduces composable compression that integrates with existing attention implementations.
- **[Resource-Efficient Reinforcement Learning Post-Training](https://arxiv.org/abs/2611.06984)** — 📄 Tackles the computational bottleneck of generating training responses in RL post-training for MoE models, where fast workers idle waiting for slow experts. Introduces elastic expert parallelism that dynamically reallocates workers based on expert availability and response length.
- **[Octopus](https://arxiv.org/abs/2611.06956)** — 📄 Introduces a multi-agent LLM framework using latent-KV branches with isolated context windows per sub-agent, avoiding KV cache duplication across parallel branches. Proposes efficient inter-branch communication via summary prefill rather than full cache exchange.
- **[Shaping & Monitoring Models](https://arxiv.org/abs/2611.07071)** — 📄 Present Mechanistic Shaping, a training framework that enforces specifications on model concepts via internal representation monitoring, not just output-level constraints. Optimizes shape losses that penalize deviation from desired concept activation patterns across layers.
- **[Server-Side Sparse Assignment](https://arxiv.org/abs/2611.07093)** — 📄 Addresses client heterogeneity in federated MoE training by proposing server-side sparse assignment that routes tokens to experts without requiring client-side expert selection. Reduces communication overhead and accommodates diverse data distributions across edge devices.
- **[Cooperative Multi-Agent Reinforcement Learning](https://arxiv.org/abs/2611.07066)** — 📄 Addresses the combinatorial complexity in MARL joint state-action spaces that hinders cooperative behavior emergence. Introduces epigraph-form guided exploration that structures intrinsic rewards to align with team objectives without distorting learning dynamics.

## Today's Synthesis

If you're serving Mixture-of-Experts models in production, the trio of LowRAM, server-side sparse assignment, and elastic expert parallelism offers a surprisingly practical stack for taming KV cache bloat and straggler bottlenecks. LowRAM's insight that attention head values are largely predictable from keys opens the door to low-rank key compression and amortized value storage, reducing memory footprint without retraining. Pair that with server-side sparse assignment, which routes tokens to experts from the server side rather than forcing heterogeneous edge devices to perform expert selection, and you cut communication overhead across federated or distributed setups. Throw in elastic expert parallelism from the RL post-training work, which dynamically reallocates workers based on expert availability and response length, and you finally solve the "fast workers idling for slow experts" problem that plagues MoE training loops. The engineer takeaway: combine test-time KV compression, server-guided routing, and dynamic parallelism adjustment into a single serving pipeline, and you can deploy larger MoE models on existing hardware while keeping latency and cost in check.
