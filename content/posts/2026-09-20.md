## Open Source Releases

**[smartmemory-core](https://pypi.org/project/smartmemory-core/1.4.104/)** — A multi-layered memory architecture stitching together graph databases, vector stores, and processing pipelines. It offers persistent, context-aware recall for AI agents, though if you already run RAG, it might feel like buying a mansion when you only need a bigger closet. 🧠

**[hol-guard](https://pypi.org/project/hol-guard/3.0.193/)** — Runtime protection and antivirus framework for AI agents, MCP servers, and plugins. Aims to block malicious package installs and tool misuse in real time, because running AI agents in production without a security detail feels increasingly like a plot hole. 🛡️

**[claude-token-saver](https://pypi.org/project/claude-token-saver/1.6.0/)** — Compiles coding tasks and patches into minimal, evidence-complete contexts for Claude. It’s token arbitrage: less context, same completeness, and a slightly kinder API bill at month-end. 💰

**[remagent](https://pypi.org/project/remagent/1.1.1/)** — Autonomous memory framework inspired by biological REM consolidation, using zero-vector techniques for long-term AI agent memory. Compatible with major LLM providers. Either the next frontier in agentic persistence or just a clever rebrand of “remember what you did last summer.” 🌙

**[fde-framework](https://pypi.org/project/fde-framework/0.1.31/)** — Framework for forward-deployed engineers to move from problem statements to deployable AI projects, tracing decisions to supporting facts and data. Markets itself as the path to reproducibility and auditability, though if your team already JIRA-izes everything, the novelty fades fast. 📄

**[hazzel](https://pypi.org/project/hazzel/1.5.3/)** — Terminal-native coding agent supporting Groq, OpenAI, Anthropic, and Mistral for on-device or remote code generation. Abstracts key management and offers a lightweight shell interface for agentic workflows. Tries to be the `git` of AI-assisted coding, but without two decades of entrenched inertia. 🛠️
